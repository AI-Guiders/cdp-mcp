## Context

На длинных срезах агент игнорирует правильные инструменты и тыкается в терминал/peek —
не потому что среда сломана, а потому что **правильный путь не первый в глазах**:

- `next[]`-подсказки умирают со следующим ходом (живут в одном ответе);
- QRH/чеклисты лежат в KB — их надо вспомнить и открыть;
- ошибка tool-not-found возвращает простыню на 150 тулов — сама жрёт контекст и
  толкает к терминалу (токсичный ответ);
- имена тулов стабильны, меняется **набор по фазе ЖЦ** (explore→…→ship) — это фича,
  но агент не видит «какой набор сейчас актуален».

Пример (Света, 2026-09-06): агент много ходов шёл peek/find по диску, игнорируя
`cdp_memory_session_route_context` — родной ориентировщик по KB — и только подсказка
оператора («где у нас проекты в KB лежат?») привела к нему; route_context за один
запрос выдал всю карту knowledge roots (chmod ugo, где проекты, куда писать).

**Operator idea (Света):** сделать в CDP **cdp_where** — по аналогии с `where.exe`
(where cmd → путь до cmd.exe): здесь `cdp_where` → **сводка по текущей точке**
(где ты, что дальше, что доступно). Плюс ввести класс **tips&tricks** — сейчас
такого понятия нет.

## Decision

### 1. `cdp_where` — сводка текущей точки

Один вызов возвращает ориентировку без чтения файлов:

```
ГДЕ ТЫ
  project root, bindings, фаза ЖЦ (подсвечена текущая), маунт/warm-состояние
ЧТО ДОСТУПНО
  актуальный набор тулов по текущей фазе (+ те, что сейчас НЕ в наборе: «появится на ship»)
ЧТО ДАЛЬШЕ
  next-жесты под текущую фазу (не повтор next[] одного ответа, а сводка фазы)
CONDITIONS
  известные блокеры и лечение: sub_failed → TryRead normalize; 401 → carrier
  desktop_no_auth; not_found на каталоге → peek file-only; …(живой список)
TIPS&TRICKS
  витрина правил хождения (см. §2)
STUCK?
  «зовешь cdp_man / route_context / cdp_open» — следующий жест по ситуации
```

Синтез из уже существующего: `cdp_session` (контекст) + `cdp_man` (TOC) +
`memory_session_route_context` (KB) — но **одной сводкой**, не тремя ходами.
Гейт: одна строка в AGENTS.md — «stuck with cdp → cdp_where».

### 2. tips&tricks — новый класс контента

Короткие правила хождения, накопленные линиями. Границы (не дубли):

| Слой | Вопрос | Суть |
|---|---|---|
| agent findings | «чему я научился» | сырой опыт, извлекается агентом после решения |
| **tips&tricks** | «как обычно ходят» | курируемая витрина правил (поднимаются из findings после практики) |
| **cdp_where** | «где я, что дальше» | живая сводка точки; tips&tricks — один из блоков |

Первый релиз (из практики этой ночи):
- mutate → peek факт → следующий шаг (не два mutate подряд);
- npm-шимы — только через `cmd /c` (PATHEXT, урок b02d343);
- KB/заметки/проекты → `memory_session_route_context` (первый жест);
- затык в имени тулзы → `cdp_man`, не гадать;
- верить БД/фактам, не OC-экрану (глюк догрузки OC-клиента);
- после deploy → `cdp_open` заново, потом мутации;
- пустой user-ход ≠ сигнал (synthetic compaction-continue opencode).

Источник пополнения — agent findings (finding → практика → tip). Колб-цикл не
вводится (Cursor-агентам не зашёл — оператор).

## Non-goals

- Не replaces `cdp_man` (полный TOC) — where = сводка точки, man = энциклопедия.
- Не replaces agent findings (сырой опыт) — витрина ссылается на них.
- No learning-cycle ритуалов (kolb) — только быстрая сводка.

## Consequences

- Ориентировка одним жестом; правильный путь становится «первым в глазах».
- Токсичные простыни tool-not-found перестают решать судьбу хода (есть where).
- Требует лёгкой поддержки в вышке: собрать фазу + набор + conditions (данные уже
  есть: session/context/tools/lifecycle).
- AGENTS.md — одна строка-указатель вместо полной карты (карта живёт в where).
