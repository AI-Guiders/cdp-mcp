# CDP-ADR-0234: Wake addressing — owner, task key, terminal misroute

**Status:** Accepted  
**Date:** 2026-10-22  
**Extends:** [CDP-ADR-0213](CDP-ADR-0213-wake-dispatcher.md), [CDP-ADR-0219](CDP-ADR-0219-habitat-state-consolidation.md), [CDP-ADR-0227](CDP-ADR-0227-wake-channel-external-subscribers.md)

## Problem

TM-wake (AutoIgnition charge) приходил в сессию, которой задача не принадлежит. Разбор
инцидента 2026-10-12 / 2026-10-21 показал четыре независимых пути:

1. **Тесты писали армы в боевой стор.** `CdpMcp.Tests` поднимали армы
   (`IdeShellIgniteTests`, `shell-bg-fremus`) прямо в `%LocalAppData%/cdp-mcp/cdp-state.witdb`.
   Живой `CdpService` видел их в общем сторе и стрелял доставку в тестовую сессию —
   `opencode run -s <placeholder session> "<charge>"`. Реальная линия просыпалась.
2. **Арм не помнил владельца.** Адресат по умолчанию — «единственная живая
   opencode-линия» из реестра; ник не проверялся перед доставкой, поэтому арм мог
   разбудить прежнюю или чужую сессию.
3. **Непривязанная цель висела вечно.** Конверт без цели (`no_session` / `no_registry`)
   оставался `pending` и стоял первым в очереди — ретраи без конца.
4. **Письмо с ключом задачи шло любой линии.** `TaskKey` в конверте не участвовал в
   выборе адресата: фильтр подписки применялся только к событийным wake.

## Decision

**1. Тесты не пишут в боевой стор.** `CdpStateStoreOverride.ForTests` — шов для
CDP-стора; `IdeIgniteArmHost` и `CideWakeDispatch` берут изолированный стор, если шов
задан. `CdpMcp.Tests/WakeTransportSubstitute` (module initializer) поднимает temp-root
стор. Тест, который пишет арм, проверяет, что арм приземлился в temp-стор.

**2. Адрес доставки — владелец.** Арм помнит `OwnerNick`:

- явно: `nick=` / `owner=`;
- при seat по умолчанию — ник линии из реестра, а если у активного TM-листа задан
  исполнитель (`Stage ~Executor`) и он известен реестру — этот исполнитель.

Перед opencode-доставкой `OwnerStillOwnsSession` проверяет, что владелец всё ещё ведёт
ту же сессию. Иначе — отказ: `no_owner` (владельца нет в реестре) или `owner_moved`
(владелец переписал сессию). Явная `session=` без владельца — не проверяется: адресат
задан намеренно.

**3. Непривязанная цель — терминальный `misroute`.** Конверт, которому не нашлось цели,
по истечении `WakeTargetMissingMaxAgeMinutes` (по умолчанию 30) становится `skipped`:
причина остаётся `no_session` / `no_registry`, в `Detail` — `misroute: target not bound
after N min`. Мёртвый конверт больше не затыкает очередь.

**4. `TaskKey` — часть адресации.** Конверт с заданным `TaskKey` доставляется только
линии, чья подписка на этот вид событий содержит совпадающий `TaskFilter`; остальные —
`skipped` с причиной `task_filter_mismatch`. Подписки без фильтра принимают всё:
доставка существующих линий не меняется.

## Non-goals

- Переписывание доставки писем по нику: письмо без `TaskKey` адресуется через реестр
  линий, как раньше.
- Отказ арма при исполнителе-человеке (`Света`): `Executor` — это «кто», а не обязательно
  линия из реестра; отказ здесь ломал бы непрерывность. Пока владелец не является линией
  из реестра, адресатом остаётся дежурная линия по реестру.
- Отказ при пустом `Executor`: отсутствие исполнителя — отсутствие адресата, но адресат
  по умолчанию из реестра остаётся осознанным компромиссом.
